## What I Learned & Key Takeaways

In this session, we looked at how Java source code moves through the build pipeline into production-ready software[cite: 1]. Understanding the progression from human-readable `.java` source code to compiled `.class` JVM bytecode, and finally into a packaged `.jar` archive, made the build process much clearer[cite: 1]. 

A major takeaway for me was repository discipline[cite: 1]. I used to think committing compiled files wasn't a big deal, but learning how binary outputs create repository bloat, merge conflicts, and environment bugs made the rule obvious: we must track `.java` source files and `pom.xml` in Git, while explicitly keeping the `target/` directory and `.class` outputs in `.gitignore`[cite: 1].

We also examined how Maven uses `pom.xml` as a build blueprint to orchestrate compilation, unit testing, and packaging via plugins like `maven-jar-plugin`[cite: 1]. This connects directly to CI/CD pipelines using tools like GitHub Actions or Jenkins, which automatically run `mvn compile` and `mvn test` whenever changes are pushed to ensure code stability before deployment[cite: 1].

Finally, we explored text encodings[cite: 1]. I realized that UTF-8 and UTF-16 aren't version updates, but different design choices[cite: 1]. UTF-8 uses 1 byte for standard ASCII characters, making it ideal for web efficiency, while UTF-16 uses 2-byte minimum units, making it far more efficient for processing scripts like CJK and serving as Java's internal string representation[cite: 1].

---

## Core Takeaways

* **Repository Cleanliness:** Commit source code (`.java`) and build blueprints (`pom.xml`); exclude generated bytecode and JARs to avoid build conflicts[cite: 1].
* **Automated Builds:** Maven uses `pom.xml` to standardize compiling, testing, and packaging across developer environments[cite: 1].
* **CI/CD Integration:** Continuous integration pipelines build and test code automatically on every push to catch bugs early[cite: 1].
* **Text Encoding Trade-offs:** UTF-8 optimizes ASCII text and web standards, whereas UTF-16 optimizes multi-byte language scripts and Java runtimes[cite: 1].
